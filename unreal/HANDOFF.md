### Fixed in the last pass (review round "ue-compile + gameplay")
1. `Private/UI/FourfoldPageBuilder.h` now includes `<string>` itself. Before, the file compiled only inside the
   unity build, so editing it on the Mac (adaptive unity) would have broken the build.
2. iOS signing: in 5.8 the generated Xcode project takes the bundle id and team from
   `[/Script/MacTargetPlatform.XcodeProjectSettings]` `BundleIdentifier` / `CodeSigningTeam`, so those are now the
   EDIT-ME keys in `Config/DefaultEngine.ini`. `IOSRuntimeSettings` mirrors them for Turnkey. The deprecated
   `bUseModernXcode` line is gone. MAC_SETUP 6.2 has been rewritten to match.
3. Chained actions are now animated. The lightning release (`l_release`, T3 `l_skybreak`), the lava pour (`f_pour`),
   Vent (`f_palm_burst`), Wind Grip (`a_pluck` → `a_guard` → `a_palm`) and Flare Dash used to drop the fighter to its
   stance, or play a Water clip on an Air move. A new logic test scans FourfoldCore for every `start_action` /
   `morph_action` id. It fails when an id resolves to no clip, or to a clip from another element.
4. The moving-wave step is now rounded like Godot (`(dir * speed) * dt` in float32). Ice-path and fire-line segments
   no longer drift by a tick.

## 2. Owner steps on the Mac (in this order)

1. **Install once** (MAC_SETUP §1): Xcode 26 (open it once, `sudo xcode-select -s /Applications/Xcode.app`), add your
   Apple ID in Xcode ▸ Settings ▸ Accounts, and add the iOS target platform to UE 5.8.3 in the Epic launcher.
2. **Signing values** (needed before an iPhone build; harmless to do now): in `unreal/Config/DefaultEngine.ini`, fill
   the four `EDIT-ME` lines (two values). `CodeSigningTeam` and `IOSTeamID` get your 10-character Team ID.
   `BundleIdentifier` (in both sections) gets `com.<yourname>.fourfold`.
3. **Build and open**: run `bash unreal/Tools/mac/run.sh` from the repository root. It builds `FourfoldEditor` into
   `logs/build_editor.log`, then opens the editor and runs the asset setup. If the build fails, stop here and send
   the log.
4. **Asset setup**: this runs automatically from step 3. You can also start it with Tools ▸ Execute Python Script ▸
   `unreal/Content/Python/fourfold_setup.py`. Wait until shader compilation (bottom right) reaches 0, then check
   `unreal/Saved/Fourfold/setup_report.json` for `failed` entries.
5. **Python API stub**: copy `unreal/Intermediate/PythonStub/unreal.py` to `unreal/Tools/py_stub/unreal.py` and commit
   it. Later rounds use it to check every editor script against your exact engine.
6. **Play on the Mac**: open Content Browser ▸ `Fourfold/Maps/L_Lab` and press Play. Try the Lab, then 1v1 vs AI
   (MAC_SETUP §5 lists the keys). For the phone look, use Settings ▸ Preview Platform ▸ iOS.
7. **iPhone / iPad** (MAC_SETUP §6): turn on Developer Mode on the device and connect it by cable. Check Project
   Settings ▸ Platforms ▸ Xcode Projects (Team ID and Bundle ID from step 2), then use Platforms ▸ iOS ▸ your device
   ▸ Launch. On the device, open the console with a four-finger tap and run `stat unit`.

## 4. Known gaps

- Unreal has never compiled or run this code (see section 1). The syntax checks used 5.8.2 public headers.
- `SpawnCatalog.cpp` (Lab spawn helper) calls `std::atan2` on floats. Godot calls it on doubles, so the Lab
  spawn-catalog counter probe drifts slightly from Godot until that call is cast to double. The review measured
  this; it is not fixed in this pass. Normal gameplay and the golden matrix are not affected.
- The Lab Tuning page has no "counter-rule thresholds" mode yet. The core already provides
  `LabRuleCells` / `LabRuleFields` / `LabSetRuleValue`; the Slate UI just doesn't call them.
- Touch layout, multi-touch and safe-area handling have only been tested synthetically and need a pass on a real
  device. Adaptive quality only steps down.
- The animation clips are hand-keyed P0–P2 quality. The skeleton matches the UE5 Mannequin, so bought mocap packs
  can be retargeted (IK Retargeter) later.
- Binary assets (materials, levels, sounds) exist only after the asset setup script has run on the Mac.
