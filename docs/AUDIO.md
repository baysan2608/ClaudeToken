# Fourfold audio

The complete sound-effect library is **procedurally synthesized**: 62 mono WAV files plus `manifest.json`,
generated by one deterministic Python script (62 original sounds plus 54 for the moveset, 116 in all). There are no samples, no recordings and no third-party audio in
the project.

| Item | Location |
|---|---|
| Generator | `tools/audio/synth_sfx.py` |
| Validator / analysis | `tools/audio/validate_sfx.py` |
| Python dependencies | `tools/audio/requirements.txt` (numpy, scipy; matplotlib only for spectrograms) |
| Output | `game/assets/audio/*.wav` and `game/assets/audio/manifest.json` |

## Regenerating

```sh
pip install numpy scipy matplotlib                  # once; matplotlib is optional
python3 tools/audio/synth_sfx.py                    # writes game/assets/audio/*.wav + manifest.json (about 4 s)
python3 tools/audio/validate_sfx.py                 # metrics + pass/fail for every file (exit code 1 on failure)
python3 tools/audio/validate_sfx.py --determinism   # renders twice into temp dirs, compares SHA-256 of every file
```

Useful options:

```sh
python3 tools/audio/synth_sfx.py --list                  # names / categories / loop flags
python3 tools/audio/synth_sfx.py --only deflect block    # re-render a subset (the manifest is merged: only the named entries change)
python3 tools/audio/synth_sfx.py --out /tmp/sfx          # render somewhere else
python3 tools/audio/synth_sfx.py --audit                 # dev check: report layers cut off while still audible
python3 tools/audio/validate_sfx.py --spectrograms OUTDIR deflect block lava_wave_loop   # PNG sheet
python3 tools/audio/validate_sfx.py --table              # markdown table of the manifest (used below)
```

Output is **byte-identical on every run** (two fresh runs and the committed files compared: 63/63 equal). Every
sound owns a fixed seed (`crc32(name)` mixed with a master seed), so changing or adding one sound never changes
another. Developed with Python 3.11, numpy 2.4.6 and scipy 1.17.1; a different numpy/scipy build may change
individual samples by an LSB, which is why the WAVs are committed rather than rebuilt in CI. Re-run the generator
only when you mean to change a sound, and commit the resulting WAVs together with the script change.

## Method

Everything is built from oscillators and filtered noise, layered as **transient + body + tail**; nothing is a
plain beep.

* **Primitives**: pitch-dropping sine "thumps" (soft-saturated with `tanh` so they carry harmonics at
  150-600 Hz: phone and tablet speakers cannot reproduce true sub-bass, so weight is implied rather than
  rendered; every hit, step and impact keeps most of its energy above 150 Hz), band-limited noise bursts, damped
  sinusoids (rings, bubbles, droplets, sparks), modal banks (stone, glass, bell), harmonic "buzz" oscillators,
  FM bells, and a synthetic-noise reverb for short tails.
* **Elements**
  * *Earth*: low saturated thuds with a mid "knock", a dead stone ring (inharmonic modes, 20-70 ms), debris
    scatter, and irregular stick-slip **grind** (random slip events drive band-limited noise, so it never
    sounds like a regular tremolo).
  * *Lava*: thick low bubbles (chirped damped sines, 85-300 Hz, with soft pops), a viscous flow bed (brown noise
    through a slowly opening low-pass), ticking/cracking for heating, hissing crust.
  * *Water/ice*: filtered-noise splashes plus bubble chirps and droplets; freeze and shatter are dense glassy
    grains over tonal twinkles.
  * *Fire*: fast-attack noise roar through a falling low-pass, pressure thump, crackle scatter.
  * *Air*: band-passed whooshes from two cascaded band-pass sections (steep skirts) with a swept centre
    frequency, a low body layer and an airy top.
  * *Lightning*: broadband crack, descending "zap" chirp, harmonic buzz tail through a moving formant, sparks.
    `lightning_redirect` adds a second crack and a bent, ring-modulated buzz.
* **Musical material** (deflect, element motifs, unlock, UI) shares one D-pentatonic tonal centre, so the four
  element motifs read as a family: earth A3-D4 (low, woody), water A5-F#5-D5 as a falling droplet ripple,
  fire D4-F#4-A4-D5 (fast bright arpeggio), air A5-E6 (high, breathy). `deflect` is a clean glassy ping at A6;
  `perfect_deflect` is the same ping plus a short rising crystalline arpeggio and sparkle sweep; `block` is a
  deliberately dark, ringless thud with almost no energy above about 2 kHz, so the two never get confused.
* **Finishing** (per file): zero-phase 22 Hz high-pass and DC removal, silence trimmed (one-shots), a 0.7 ms
  fade-in and a cosine fade-out, soft crest limiting, then peak normalisation to **-3 dBFS** (the ambience bed
  to **-18 dBFS**), written as 16-bit mono 44.1 kHz.
* **Loops are periodic by construction**, so the seam is continuous with no audible crossfade: spectrally
  shaped noise is synthesised circularly, LFOs have whole numbers of cycles per loop, event scatter wraps around
  the end, time-varying filters are warm-started over one extra period, and the rising-tone loops are
  phase-aligned Shepard-Risset glissandi. The generator then rotates each loop to the start point with the
  smoothest seam. Each loop WAV also carries a `smpl` chunk (loop 0 to N-1) so that Godot's default
  "Detect From WAV" import turns looping on.

## Moveset extension (MOVESET section 12): 54 new sounds

Rendered with `synth_sfx.py --only <new names>` (the manifest keeps the 62 original entries untouched and appends the
new ones; a full render reproduces the original 62 WAVs byte-for-byte, so nothing existing changed). Same method:
transient + body + tail, per-name fixed seed, D-pentatonic motifs for the tonal cues, -3 dBFS, periodic loops with

## Manifest

`game/assets/audio/manifest.json` maps each file name (without `.wav`) to
`{category, loop, duration_s, suggested_volume_db, max_voices, notes}`. Categories are `movement`, `combat`,
`earth`, `thermal`, `water`, `fire`, `lightning`, `air`, `ui`, `ambience`, and for the moveset `metal`, `sand`, `magma`, `ice`, `mist`, `plant`, `system`.

`suggested_volume_db` is derived, not guessed: the generator measures each file's loudest 100 ms RMS and picks the
volume (never above 0 dB, never below -24 dB, rounded to 0.5 dB) that brings it to a per-sound target level, so that
steps sit well below hits, hits below blasts, loops below one-shots and UI below combat. Because files are
normalised to -3 dBFS, the volumes are attenuations: apply them as the `volume_db` of the player (or as a gain in
your sound manager) and trim with bus levels on top. `max_voices`: loops 1-2, impacts 3-4, steps 2, large blasts,
slams and strikes 2, UI 1-4.

## Mixing guidance

**Bus layout** (Godot `AudioServer` / `default_bus_layout.tres`):

```
Master        limiter, ceiling -1 dB (safety only; the files already peak at -3 dBFS)
  SFX         gameplay one-shots and loops; high-pass at about 40 Hz (phone speakers cannot use sub-bass)
  UI          ui_*, element_*, unlock, challenge_fail; independent of any gameplay ducking
  Ambience    amb_courtyard_loop and later environment beds; about -6 dB, optional gentle low-pass
```

Route category `ui` to UI, `ambience` to Ambience and every other category to SFX. If the bed ever gets in the
way, duck Ambience by 3-4 dB under `guard_break`, `knockdown`, `lightning_strike` and `fire_release`.

**Voice caps**: honour `max_voices` per sound with a small player pool per file. When a pool is full, steal the
oldest voice and give it a 20-30 ms fade instead of cutting it dead. Keep a global cap of roughly 24-32
simultaneous gameplay voices on iPhone-class hardware. Footsteps: 2 voices, rotate the four variants without
immediate repeats, add random +/-1.5 dB volume and +/-4% `pitch_scale` (impacts: +/-6% pitch, +/-1 dB).

**Loops**: never restart a loop per frame or per event. Start it once when its state begins (fade the volume up
over 80-200 ms), drive `volume_db` / `pitch_scale` for intensity, and fade out (100-250 ms) before `stop()`.
Guard every start with `if not player.playing`, and keep one voice per loop id (`max_voices` 1-2 only allows a
short overlap while the old instance fades out). The files already loop seamlessly; do not add a second
crossfade. The importer's default `edit/loop_mode = Detect From WAV` reads the embedded loop points; if a loop was
imported with another mode, set it to Forward with begin 0 and end -1.

**Import settings**: the WAV importer defaults are fine (`edit/normalize` off; Godot's default QOA compression is
transparent for these). If you ever hear a tick at a loop seam, import that loop with `compress/mode = Disabled`.
Godot writes its `.import` files next to the WAVs; they are generated, not part of the audio source.

**Positional audio**: the files are mono on purpose. Use `AudioStreamPlayer3D` (or 2D) with distance attenuation for
world sounds and a plain `AudioStreamPlayer` for UI. Keep `deflect`, `perfect_deflect` and `block` non-positional
(or very close) so parry feedback always reads clearly.

**Combos**: play `perfect_deflect` *instead of* `deflect` (it already contains the ping). Lava chain:
`heat_crackle_loop`, `melt_rise`, `lava_bubble_loop` and `lava_wave_loop`, `lava_splat`, `crust_hiss`,
`cool_crack`. Water: `water_draw_loop`, then `water_whip` or `water_splash`; `freeze` then `ice_shatter`, later
`ice_melt_drip` and `steam_hiss`. Fire: `fire_charge_loop` then `fire_release`. Lightning:
`lightning_charge_loop` then `lightning_strike` (or `lightning_redirect`), `conduct_buzz` over water or metal.
